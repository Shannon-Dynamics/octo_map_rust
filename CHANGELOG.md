## [Unreleased]

Nothing has been released yet. This section describes the repository as it
stands, which is what the first release will contain.

### Added

- **A pure-Rust port of OctoMap C++ 1.10.0**, in two crates: `octomap-core`
  (the library, no runtime dependencies) and `octomap-ros` (ROS 2 message
  conversions that do not depend on ROS).
- **A ROS 2 mapping node**, `ros2/octomap_server_rs`, with the same topics,
  services and parameter names as the C++ `octomap_server`. It is a separate
  Cargo workspace so that the library builds on machines without ROS.
- **A differential test suite** against fixtures generated by the C++
  reference, comparing floating point as raw IEEE-754 bit patterns rather than
  with a tolerance.
- **Parser robustness tests**: round-trip properties for both file formats,
  every truncation of a valid file, thousands of single-byte corruptions, and
  random `PointCloud2` geometry. The property they assert is that malformed
  input produces an error rather than a panic or an out-of-range read.
- **Documentation**: a tutorial that assumes no prior OctoMap knowledge, a
  code tour, architecture and verification documents, ADRs for every deliberate
  divergence from the reference, and operational runbooks.
- **Project policy documents**: [`SAFETY.md`](SAFETY.md),
  [`SECURITY.md`](SECURITY.md), [`CONTRIBUTING.md`](CONTRIBUTING.md),
  [`ROADMAP.md`](ROADMAP.md), and a release process in
  [`docs/RELEASING.md`](docs/RELEASING.md).
- **CI** covering formatting, Clippy with warnings denied, tests,
  documentation, the declared MSRV, RustSec advisories, documentation links and
  crate packaging, on Linux and Windows.
- **Supply-chain configuration**: [`deny.toml`](deny.toml) pinning the licences
  permitted in the dependency tree and rejecting non-registry sources.

### Safety

- `unsafe_code = "forbid"` at the workspace level: the compiler rejects an
  `unsafe` block anywhere in the repository rather than a reviewer having to
  catch it.
- Verified under Miri with strict provenance: the unit test suites of both
  crates and the `PointCloud2` robustness tests execute without undefined
  behaviour being detected.
- Integer arithmetic in `PointCloud2` decoding is checked rather than wrapping,
  so a message declaring an extreme geometry is rejected instead of wrapping a
  length computation on a 32-bit target.

### Documentation

- All documentation is in English.
- Every documented command corresponds to something the repository accepts, and
  every code sample compiles — the quick start is a doc-test.

### Known limitations

Carried into the first release, and listed in the README rather than hidden:
the API is pre-1.0 and may change; several derived tree types from the
reference are not implemented; the legacy headerless `.bt` format is rejected;
insertion is single-threaded; and big-endian platforms are unsupported.
